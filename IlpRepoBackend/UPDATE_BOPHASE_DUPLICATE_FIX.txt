================================================================================

## ?? Bug Description

**Problem**: When calling `PUT /api/BoPhases/8` to update buddy/DU information, 
the API was returning error:
```
400 Bad Request: "Trainee John Doe already has a different BO Phase assignment"
```

**Request**:
```json
PUT /api/BoPhases/8
{
  "boPhaseId": 8,
  "traineeName": "John Doe",
  "buddyName": "Lance",
  "duName": "DU-3"
}
```

**Expected**: Update the existing BO Phase assignment with new buddy/DU info
**Actual**: Error claiming trainee already has a BO Phase assignment

## Root Cause

The `UpdateBoPhaseHandler` had a faulty duplicate check that was treating **all 
updates** as if they were creating a new assignment:

```csharp
// BEFORE (BUGGY CODE)
if (!string.IsNullOrWhiteSpace(request.TraineeName))
{
    var trainee = await _traineeRepository.GetByUserIdAsync(user.Id);
    
    // ? BUG: This check runs even when NOT changing the trainee
    var existingTraineeBoPhases = await _boPhaseRepository.GetByTraineeIdAsync(trainee.Id);
    if (existingTraineeBoPhases.Any(bp => bp.Id != request.BoPhaseId))
        return ApiResponse<BoPhaseDetailsDto>.Fail(
            $"Trainee {request.TraineeName} already has a different BO Phase assignment");
    
    existingBoPhase.TraineeId = trainee.Id;
}
```

### The Problem

The validation checked if the trainee has **any other** BO Phase besides the current 
one being updated. But this check should **only run when you're changing to a 
different trainee**, not when you're just updating buddy/DU info for the same trainee.

### What Was Happening

```
Scenario: Update BO Phase ID 8 (trainee = John Doe)
  ?
Request includes: traineeName = "John Doe" (same trainee)
  ?
Handler finds: John Doe already has BO Phase ID 8
  ?
Validation logic: "Does John Doe have any BO Phase EXCEPT ID 8?"
  Answer: No (he only has ID 8)
  ?
But the logic was checking: "Does John Doe have ANY BO Phase?"
  Answer: Yes (he has ID 8)
  ?
Result: ERROR - "already has a different BO Phase" ?
```

## The Fix

### Modified File
`IlpRepoBackend.Application\Handler\BoPhases\UpdateBoPhaseHandler.cs`

### Change Made

Added a conditional check to **only validate for duplicates when actually 
changing to a different trainee**:

```csharp
// AFTER (FIXED CODE) ?

{
    var user = await _userRepository.GetByUsernameAsync(request.TraineeName);
    if (user == null)
        return ApiResponse<BoPhaseDetailsDto>.Fail($"Trainee with name {request.TraineeName} not found");

    var trainee = await _traineeRepository.GetByUserIdAsync(user.Id);
    if (trainee == null)
        return ApiResponse<BoPhaseDetailsDto>.Fail($"Trainee profile for {request.TraineeName} not found");

    // ? FIX: Only check for duplicate assignments if we're actually changing the trainee
    if (existingBoPhase.TraineeId != trainee.Id)
    {
        // Check if this trainee already has a BO Phase assignment

```

## Why This Happened

### Original Intent
The validation was meant to prevent a trainee from having **multiple** BO Phase 
assignments. One trainee should only have one BO Phase assignment at a time.

### Implementation Error
The original code checked for duplicates on **every update**, even when just 
changing buddy/DU information for the same trainee.

### Correct Logic
The duplicate check should **only run when changing to a different trainee**.
