================================================================================
              BATCH STATUS AUTO-CALCULATION IMPLEMENTATION
================================================================================

## Overview
Updated the Batch CREATE and UPDATE APIs to automatically calculate the batch 
status based on the start date and end date, rather than accepting it from the 
user or defaulting to "NotStarted".

## Problem Statement
Previously, the batch status was:
1. Included as a property in CreateBatchCommand and UpdateBatchCommand
2. Had a default value of "NotStarted"
3. Could be manually set by the user (in Update)
4. Not consistently calculated based on actual dates

This led to inconsistent batch statuses that didn't reflect the actual state 
based on dates.

## Solution Implemented

### Status Calculation Logic
The status is now automatically calculated based on the current date (UTC) 
compared to the batch start and end dates:

```csharp
private BatchStatus CalculateStatus(DateTime? startDate, DateTime? endDate)
{
    var now = DateTime.UtcNow;

    // Both dates are null
    if (!startDate.HasValue && !endDate.HasValue)
    {
        return BatchStatus.NotStarted;
    }

    // Both dates are provided
    if (startDate.HasValue && endDate.HasValue)
    {
        if (now < startDate.Value)
            return BatchStatus.NotStarted;  // Before start date
        if (now > endDate.Value)
            return BatchStatus.Completed;   // After end date
        return BatchStatus.Ongoing;          // Between start and end
    }

    // Only start date provided
    if (startDate.HasValue && !endDate.HasValue)
    {
        return now < startDate.Value ? BatchStatus.NotStarted : BatchStatus.Ongoing;
    }

    // Only end date provided
    return endDate.Value >= now ? BatchStatus.Ongoing : BatchStatus.Completed;
}
```

### Status Rules

| Condition | Status |
|-----------|--------|
| No dates provided | NotStarted |
| Current date < Start date | NotStarted |
| Start date ? Current date ? End date | Ongoing |
| Current date > End date | Completed |
| Only start date, Current date ? Start date | Ongoing |
| Only end date, Current date ? End date | Ongoing |
| Only end date, Current date > End date | Completed |

## API Usage Examples

### Create Batch - Status Auto-Calculated

**Request**:
```json
POST /api/Batch
{
  "batchName": "Software Development Batch 2024",
  "batchTypeId": 1,
  "startDate": "2024-03-01",
  "endDate": "2024-12-31"
}
```

**Response** (if current date is 2024-01-15):
```json
{
  "id": 1,
  "batchName": "Software Development Batch 2024",
  "batchTypeId": 1,
  "status": "NotStarted",  // Auto-calculated (before start date)
  "startDate": "2024-03-01",
  "endDate": "2024-12-31"
}
```

**Response** (if current date is 2024-06-15):
```json
{
  "id": 1,
  "batchName": "Software Development Batch 2024",
  "batchTypeId": 1,
  "status": "Ongoing",  // Auto-calculated (between dates)
  "startDate": "2024-03-01",
  "endDate": "2024-12-31"
}
```

**Response** (if current date is 2025-01-15):
```json
{
  "id": 1,
  "batchName": "Software Development Batch 2024",
  "batchTypeId": 1,
  "status": "Completed",  // Auto-calculated (after end date)
  "startDate": "2024-03-01",
  "endDate": "2024-12-31"
}
```

## Benefits

### ? Data Integrity
- Batch status always reflects the actual state based on dates
- No manual status updates needed
- Consistent status across all batches

### ? Simplified API
- Users don't need to calculate or provide status
- Reduced risk of user error
- Clearer API contract

### ? Automatic Updates
- Status is recalculated every time batch is updated
- Status changes automatically when dates are modified
- No need for scheduled jobs to update status

### ? Business Logic Centralization
- All status calculation logic is in one place
- Easy to maintain and modify
- Consistent across Create and Update operations

## Important Notes

### 1. Status is Read-Only for Users
Users can no longer set the status manually. It's always calculated based on:
- Current date (UTC)
- Batch start date
- Batch end date

### 2. Timezone Consideration
Status calculation uses `DateTime.UtcNow` to ensure consistency across different 
timezones. All dates are compared in UTC.

### 3. Null Date Handling
If dates are not provided (null), the batch defaults to "NotStarted" status.

### 4. Backward Compatibility
**Breaking Change**: Any existing API clients that were sending `status` in the 
request body will need to be updated to remove this field. The field is no 
longer accepted and will be ignored.

## Frontend Integration

### Updated API Service
```javascript
// services/batchService.js
import { api } from '../api/ApiClient';

export const batchService = {
  // Create batch - NO status field
  createBatch: async (batchData) => {
    const payload = {
      batchName: batchData.batchName,
      batchTypeId: batchData.batchTypeId,
      startDate: batchData.startDate,
      endDate: batchData.endDate,
      phases: batchData.phases
      // NO status field - it's auto-calculated
    };
    return await api.post('/Batch', payload);
  },

  // Update batch - NO status field
  updateBatch: async (id, batchData) => {
    const payload = {
      batchName: batchData.batchName,
      batchType: batchData.batchType,
      startDate: batchData.startDate,
      endDate: batchData.endDate
      // NO status field - it's auto-calculated
    };
    return await api.put(`/Batch/${id}`, payload);
  }
};
```

### React Component Example
```jsx
import React, { useState } from 'react';
import { batchService } from '../services/batchService';

const CreateBatchForm = () => {
  const [formData, setFormData] = useState({
    batchName: '',
    batchTypeId: 1,
    startDate: '',
    endDate: ''
    // NO status field needed
  });

  const handleSubmit = async (e) => {
    e.preventDefault();
    try {
      const result = await batchService.createBatch(formData);
      console.log('Created batch:', result);
      console.log('Status was auto-calculated to:', result.status);
      alert(`Batch created with status: ${result.status}`);
    } catch (error) {
      alert('Error: ' + error.message);
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="text"
        placeholder="Batch Name"
        value={formData.batchName}
        onChange={(e) => setFormData({...formData, batchName: e.target.value})}
        required
      />
      
      <input
        type="date"
        value={formData.startDate}
        onChange={(e) => setFormData({...formData, startDate: e.target.value})}
      />
      
      <input
        type="date"
        value={formData.endDate}
        onChange={(e) => setFormData({...formData, endDate: e.target.value})}
      />
      
      <button type="submit">Create Batch</button>
      
      <p>Status will be automatically calculated based on the dates</p>
    </form>
  );
};
```

## Migration Guide

### For Existing Batches
Existing batches in the database will keep their current status until they are 
updated. When updated, the status will be recalculated automatically.

### For Frontend Applications
1. Remove `status` field from all Create Batch forms
2. Remove `status` field from all Update Batch forms
3. Display status as read-only (from API response)
4. Update UI to show that status is auto-calculated

### For API Clients
1. Remove `status` from POST /api/Batch requests
2. Remove `status` from PUT /api/Batch/{id} requests
3. Always use the `status` value from responses (don't cache it)
