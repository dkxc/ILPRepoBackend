================================================================================
                              USER MANAGEMENT APIs
================================================================================

1. GET /api/User
   Description: Get all users
   Method: GET
   Response: List of User objects
   
2. GET /api/User/{id}
   Description: Get user by ID
   Method: GET
   Parameters: id (integer) - User ID
   Response: User object
   
3. GET /api/User/username/{username}
   Description: Get user by username
   Method: GET
   Parameters: username (string) - Username
   Response: User object
   
4. POST /api/User
   Description: Create new user
   Method: POST
   Request Body:
   {
     "username": "string",
     "email": "string",
     "password": "string",
     "role": "Admin|Trainee|Mentor" (enum),
     "isActive": true
   }
   Response: Created user object
   
5. PUT /api/User/{id}
   Description: Update user
   Method: PUT
   Parameters: id (integer) - User ID
   Request Body:
   {
     "id": integer,
     "username": "string",
     "email": "string",
     "role": "Admin|Trainee|Mentor",
     "isActive": true
   }
   Response: Updated user object
   
6. DELETE /api/User/{id}
   Description: Delete user
   Method: DELETE
   Parameters: id (integer) - User ID
   Response: 204 No Content (success) or 404 Not Found

================================================================================
                            BATCH MANAGEMENT APIs
================================================================================

7. GET /api/Batch
   Description: Get all batches with batch types and phases
   Method: GET
   Response: List of Batch objects with related data
   
8. GET /api/Batch/{id}
   Description: Get batch by ID with batch type and phases
   Method: GET
   Parameters: id (integer) - Batch ID
   Response: Batch object with BatchType and Phases details
   
9. POST /api/Batch
   Description: Create new batch with phases (Status auto-calculated)
   Method: POST
   Request Body:
   {
     "batchName": "string",
     "batchTypeId": integer (optional - BatchType ID),
     "startDate": "2024-01-01" (date, optional),
     "endDate": "2024-12-31" (date, optional),
     "phases": [
       {
         "phaseType": "string",
         "phaseTypeId": integer (optional - PhaseType ID),
         "startDate": "2024-01-01",
         "endDate": "2024-03-31"
       }
     ]
   }
   Status Calculation Rules:
   - NotStarted: Current date < Start date
   - Ongoing: Start date ? Current date ? End date
   - Completed: Current date > End date
   
   Response: Created batch with auto-calculated status (HTTP 201)
   
10. PUT /api/Batch/{id}
    Description: Update batch including phases (Status auto-calculated)
    Method: PUT
    Parameters: id (integer) - Batch ID
    Request Body:
    {
      "batchName": "string",
      "batchTypeId": integer (optional),
      "startDate": "2024-01-01" (date, optional),
      "endDate": "2024-12-31" (date, optional),
      "phases": [
        {
          "phaseType": "string",
          "phaseTypeId": integer (optional),
          "startDate": "2024-01-01",
          "endDate": "2024-03-31"
        }
      ]
    }
    Note: Phases array replaces all existing phases
    Response: Updated batch with recalculated status
    
11. DELETE /api/Batch/{id}
    Description: Delete batch (validates no trainees/phases/schedules)
    Method: DELETE
    Parameters: id (integer) - Batch ID
    Response: 204 No Content (success) or 400 Bad Request with error message

24. PUT /api/Trainees/{traineeId}/training-details
    Description: Update training details for a specific trainee
    Method: PUT
    Parameters: traineeId (integer) - Trainee ID
    Request Body:
    {
      "buddyName": "string" (optional - creates buddy if not exists),
      "duName": "string" (optional - creates DU if not exists),
      "ojtMentor": "string" (optional),
      "location": "string" (optional)
    }
    Notes:
    - All fields are optional - only provided fields will be updated
    - Creates BoPhase record if updating buddy and none exists
    - Creates TraineeDu record if updating OJT/DU/Location and none exists
    - Auto-creates DU and Buddy records if they don't exist
    - Updates existing records if they already exist
    Response: ApiResponse with updated TraineeTrainingDetailsDto
    Example Response:
    {
      "status": 200,
      "succeeded": true,
      "message": "Request processed successfully",
      "data": {
        "traineeId": 1,
        "traineeName": "john.doe",
        "email": "john.doe@example.com",
        "batchName": "Software Development Batch 2024",
        "buddyName": "Jane Smith",
        "buddyDU": "Digital Engineering",
        "ojtMentor": "Mike Johnson",
        "duAllocated": "Digital Engineering",
        "location": "Bangalore"
      }
    }
    Status Codes:
    - 200 OK: Training details updated successfully
    - 400 Bad Request: Validation error
    - 404 Not Found: Trainee not found

================================================================================
                           COMMON FEATURES
================================================================================

Validation Rules:
1. Email uniqueness is enforced (Users and Trainees)
2. Aadhaar ID uniqueness is enforced (Trainees)
3. Username is NOT required to be unique
4. All POST/PUT endpoints validate required fields

Auto-Creation Features:
5. DU names are created automatically if they don't exist
6. Buddy records are created automatically if they don't exist
7. BatchType can be specified by ID

Database Features:
8. All timestamps (CreatedAt, UpdatedAt) are managed automatically
9. Cascade delete behaviors prevent orphaned records
10. Navigation properties loaded with .Include() for complete data

Status Management:
11. Batch status is AUTO-CALCULATED based on dates (cannot be set manually)
12. Status recalculates on every batch create/update

================================================================================
                              KEY FEATURES
================================================================================

Batch Management:
- Auto-calculated status based on dates
- Support for phases with phase types
- Validation prevents deletion if has trainees/phases/schedules

Trainee Management:
- Automatic user account creation
- Username can be non-unique (multiple trainees can share names)
- Email must be unique
- Aadhaar ID must be unique

BO Phase & TraineeDu:
- Auto-creates DU and Buddy records as needed
- Bulk upload support for batch assignments
- Links trainees to buddies and delivery units

================================================================================
                              ERROR HANDLING
================================================================================

Common HTTP Status Codes:
- 200 OK: Successful GET/PUT
- 201 Created: Successful POST
- 204 No Content: Successful DELETE
- 400 Bad Request: Validation errors, business rule violations
- 404 Not Found: Resource not found
- 500 Internal Server Error: Server-side errors

Common Error Scenarios:
- Duplicate email: "Email already exists"
- Duplicate Aadhaar: "Aadhaar ID already exists"
- Missing required fields: Validation error messages
- Batch deletion with data: "Cannot delete batch - has trainees/phases/schedules"
- Invalid foreign keys: "Entity not found" errors
