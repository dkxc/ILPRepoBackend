================================================================================
                     PROJECT MANAGEMENT APIs - COMPLETE SUMMARY
================================================================================

Base URL: https://localhost:7224/api/Projects
Content-Type: application/json

================================================================================
                              OVERVIEW
================================================================================

The Project Management APIs allow you to manage trainee projects including:
- Creating and managing projects
- Assigning team members (trainees) with roles
- Assigning mentors and POCs to projects
- Managing project links (GitHub, Jira, etc.)
- Tracking project status and progress
- Viewing project details with team composition
- Bulk project creation for batches

================================================================================
                          PROJECT ENTITY STRUCTURE
================================================================================

Project Properties:
- Id: integer (Primary Key)
- ProjectName: string (Required, max 100 characters)
- Status: ProjectStatus enum (Required)
- Progress: integer (0-100, default 0)
- Technology: string (Technology stack, max 255 characters)
- CreatedAt: DateTime (UTC, auto-managed)
- UpdatedAt: DateTime (UTC, auto-managed)

Relationships:
- ProjectTeams: Collection of team members (trainees) with roles
- MentersForProjects: Collection of assigned mentors
- PocsForProjects: Collection of assigned POCs
- ProjectLinks: Collection of project-related links
- DocumentRequests: Collection of document requests for this project

================================================================================
                          PROJECT STATUS ENUM
================================================================================

ProjectStatus Values:
- NotStarted: Project has not begun
- InProgress: Project is actively being worked on
- OnHold: Project is temporarily paused
- Completed: Project is finished
- Cancelled: Project has been cancelled

================================================================================
                          PROJECT ROLE ENUM
================================================================================

ProjectRole Values (for team members):
- Trainee: Regular team member
- TeamLead: Team leader
- ScrumMaster: Scrum master for the project

## 1. CREATE PROJECT (POST /api/Projects)

**Description**: Create a new project with team members, mentors, and POCs

**Authorization**: Requires Admin role

**Request Body**:
```json
{
  "projectName": "E-Commerce Platform",
  "technology": "React, Node.js, MongoDB",
  "status": "InProgress",
  "progress": 25,
  "teamMemberEmails": [
    "john.doe@example.com",
    "jane.smith@example.com"
  ],
  "teamLeadEmail": "alice.johnson@example.com",
  "scrumMasterEmail": "bob.williams@example.com",
  "mentorIds": [1, 2],
  "pocIds": [1]
}
```

**Request Fields**:
- `projectName` (required): Name of the project
- `technology` (required): Technology stack used
- `status` (required): ProjectStatus enum value
- `progress` (optional): Progress percentage (0-100), default 0
- `teamMemberEmails` (optional): Array of trainee emails for team members
- `teamLeadEmail` (optional): Email of team lead (must be a trainee)
- `scrumMasterEmail` (optional): Email of scrum master (must be a trainee)
- `mentorIds` (optional): Array of mentor IDs
- `pocIds` (optional): Array of POC IDs

**Validation**:
- All emails must exist as trainees
- Mentor IDs must exist
- POC IDs must exist
- Team lead and scrum master cannot be the same person
- Duplicate emails are automatically removed

**Success Response**: 201 Created
```json
{
  "status": 201,
  "succeeded": true,
  "message": "Project created successfully",
  "data": {
    "id": 1,
    "projectName": "E-Commerce Platform",
    "technology": "React, Node.js, MongoDB",
    "status": "InProgress",
    "progress": 25,
    "teamMembers": [...],
    "mentors": [...],
    "pocs": [...]
  }
}
```

**Error Response**: 400 Bad Request
```json
{
  "status": 400,
  "succeeded": false,
  "message": "Trainee with email john.doe@example.com not found",
  "data": null
}
```

## 8. UPSERT PROJECT LINK (PUT /api/Projects/{id}/links)

**Description**: Add a new project link or update an existing one based on link type

**Parameters**: 
- `id` (integer, required): Project ID

**Request Body**:
```json
{
  "linkId": 1,
  "linkUrl": "https://github.com/team/ecommerce-v2"
}
```

**Request Fields**:
- `linkId` (required): Link type ID (references Link entity)
- `linkUrl` (required): URL for the link

**Behavior**:
- If a project link with the same `linkId` exists, it updates the URL
- If no link exists for that `linkId`, it creates a new one

**Success Response**: 200 OK
```json
{
  "status": 200,
  "succeeded": true,
  "message": "Request processed successfully",
  "data": true
}
```

**Example Link Types**:
- 1: GitHub Repository
- 2: Jira Board
- 3: Confluence Wiki
- 4: Deployment URL
- (Link types are defined in the Link entity)

## 9. DELETE PROJECT (DELETE /api/Projects/{id})

**Description**: Delete a project and all related data

**Parameters**: 
- `id` (integer, required): Project ID

**Example Request**: DELETE /api/Projects/1

**Success Response**: 200 OK
```json
{
  "message": "Project deleted successfully"
}
```

**Error Response**: 400 Bad Request
```json
{
  "message": "Project not found or cannot be deleted"
}
```

**Cascade Delete**:
When a project is deleted, the following are also deleted:
- All project team assignments (ProjectTeam records)
- All mentor assignments (MenterForAProject records)
- All POC assignments (PocsForProject records)
- All project links (ProjectLink records)
- Related document submissions and requests (if configured)

**Notes**:
- This is a permanent delete operation
- Use with caution in production

================================================================================
                          BUSINESS LOGIC
================================================================================

### Team Member Assignment Logic:

1. **Validation Phase**:
   - All emails are validated to ensure trainees exist
   - Team lead email is validated separately
   - Scrum master email is validated separately
   - Mentors and POCs are validated by ID

2. **Role Conflict Resolution**:
   - If team lead is in team member list, they are removed from team members
   - If scrum master is in team member list, they are removed from team members
   - This ensures no duplicate assignments

3. **Role Assignment Order**:
   - Team members are added first with Role = Trainee
   - Team lead is added with Role = TeamLead
   - Scrum master is added with Role = ScrumMaster

### Update Logic:

When updating a project:
1. Previous team members are completely removed
2. Previous mentors are completely removed
3. Previous POCs are completely removed
4. New assignments are created from scratch
5. This ensures clean state without orphaned records

### Link Management:

Project links use an "upsert" pattern:
- If a link with the same `linkId` (link type) exists ? UPDATE
- If no link exists for that `linkId` ? CREATE
- This ensures only one link per link type per project

================================================================================
                          DATABASE RELATIONSHIPS
================================================================================

Project has:
- Many ProjectTeams (trainees assigned to project)
- Many MentersForProjects (mentors assigned to project)
- Many PocsForProjects (POCs assigned to project)
- Many ProjectLinks (links associated with project)
- Many DocumentRequests (document requests for project)

Trainee can have:
- Many ProjectTeams (can be in multiple projects)

Mentor can have:
- Many MentersForProjects (can mentor multiple projects)

POC can have:
- Many PocsForProjects (can be POC for multiple projects)

Link can have:
- Many ProjectLinks (can be used in multiple projects)

================================================================================
                          BEST PRACTICES
================================================================================

1. **Creating Projects**:
   - Always include project name and technology
   - Set appropriate status (usually "NotStarted" or "InProgress")
   - Assign team members before project start
   - Assign mentors for guidance

2. **Updating Projects**:
   - Use full update (PUT /projects/{id}) for major changes
   - Use technology update (PUT /projects/{id}/technology) for tech stack only
   - Use link upsert (PUT /projects/{id}/links) for managing links

3. **Querying Projects**:
   - Use GET /projects for listing all projects
   - Use GET /projects/{id}/details for comprehensive view
   - Details endpoint includes team, links, and submissions

4. **Deleting Projects**:
   - Confirm deletion before calling API
   - Be aware of cascade deletes
   - Consider archiving instead of deleting in production

5. **Team Management**:
   - Assign team lead for leadership
   - Assign scrum master for agile practices
   - Regular team members have "Trainee" role

### Example: Create Project Form

```typescript
const createProject = async (formData) => {
  const projectData = {
    projectName: formData.projectName,
    technology: formData.technology,
    status: formData.status || 'NotStarted',
    progress: formData.progress || 0,
    teamMemberEmails: formData.teamMembers.map(m => m.email),
    teamLeadEmail: formData.teamLead?.email,
    scrumMasterEmail: formData.scrumMaster?.email,
    mentorIds: formData.mentors.map(m => m.id),
    pocIds: formData.pocs.map(p => p.id)
  };

  const response = await fetch('/api/Projects', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(projectData)
  });

  return response.json();
};
```
