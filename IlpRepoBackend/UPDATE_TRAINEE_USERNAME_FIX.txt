```csharp
public async Task<ApiResponse<TraineeDto>> Handle(
    UpdateTraineeCommand request, 
    CancellationToken cancellationToken)
{
    var trainee = await _traineeRepository.GetByIdAsync(request.Id);
    if (trainee == null)
        return ApiResponse<TraineeDto>.Fail($"Trainee with ID {request.Id} not found");

    // ? Get the user account
    var currentUser = await _userRepository.GetByIdAsync(trainee.UserId);
    if (currentUser == null)
        return ApiResponse<TraineeDto>.Fail($"User account for trainee not found");

    // ? Update username if provided
    if (!string.IsNullOrWhiteSpace(request.Username) && 
        request.Username != currentUser.Username)
    {
        currentUser.Username = request.Username;
        currentUser.UpdatedAt = DateTime.UtcNow;
    }

    // Update email with validation
    if (!string.IsNullOrWhiteSpace(request.Email) && request.Email != trainee.Email)
    {
        if (request.Email != currentUser.Email && 
            await _userRepository.EmailExistsAsync(request.Email))
        {
            return ApiResponse<TraineeDto>.Fail("Email already exists");
        }
        
        currentUser.Email = request.Email;
        currentUser.UpdatedAt = DateTime.UtcNow;
    }

    // ? Save user updates if any changes were made
    if (!string.IsNullOrWhiteSpace(request.Username) || 
        (!string.IsNullOrWhiteSpace(request.Email) && request.Email != trainee.Email))
    {
        await _userRepository.UpdateAsync(currentUser);
    }

    // Update trainee table
    trainee.Email = request.Email ?? trainee.Email;
    trainee.PhoneNo = request.PhoneNo ?? trainee.PhoneNo;
    trainee.Status = request.Status;
    // ... update other trainee fields
    trainee.UpdatedAt = DateTime.UtcNow;

    var updatedTrainee = await _traineeRepository.UpdateAsync(trainee);
    var traineeDto = _mapper.Map<TraineeDto>(updatedTrainee);
    traineeDto.Username = currentUser.Username;  // ? Ensure updated username is returned
    
    return ApiResponse<TraineeDto>.Success(traineeDto);
}
```

## Key Implementation Details

### 1. Username is Optional
- If username is not provided in request, it remains unchanged
- Only updates if a new value is provided and it's different from current

### 2. Email Validation
- Email uniqueness is still validated across all users
- Prevents duplicate email addresses

### 3. Timestamp Management
- Both User.UpdatedAt and Trainee.UpdatedAt are updated
- Uses UTC time for consistency

### 4. Atomic Updates
- User table is updated first
- Then Trainee table is updated
- If email validation fails, neither update occurs

### 5. Response Includes Updated Username
- Handler explicitly sets `traineeDto.Username = currentUser.Username`
- Ensures response reflects the updated value

## Why This Happened

### Design Pattern: Split Entity Approach
The system uses a split entity approach where:
- **User**: Authentication/account info (Username, Email, Password, Role)
- **Trainee**: Role-specific info (Address, Health, Emergency contacts, etc.)

This design is common in systems with multiple user types (Admin, Trainee, Mentor).

### Original Oversight
When the `UpdateTraineeCommand` was created, it focused on trainee-specific 
fields (address, health info, etc.) but missed that username is stored in 
the User table.

## Related Considerations

### Username Uniqueness
Unlike email, **username is NOT required to be unique**:
- Multiple trainees can have the same name
- This is intentional to allow common names like "John Smith"
- Email serves as the unique identifier

### Example: Multiple Trainees with Same Name
```json
[
  {
    "id": 1,
    "userId": 10,
    "username": "John Smith",
    "email": "john.smith1@example.com"
  },
  {
    "id": 2,
    "userId": 11,
    "username": "John Smith",
    "email": "john.smith2@example.com"
  }
]
```
This is valid and supported.
