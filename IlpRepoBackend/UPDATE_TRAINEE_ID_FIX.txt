## ?? Bug Description

**Problem**: When calling `PUT /api/Trainees/19`, the API was returning error:
"Trainee with ID 30 not found" instead of updating trainee ID 19.

**Root Cause**: The trainee with Id=19 has UserId=30. The request body was 
including `id: 30` (the UserId instead of the trainee Id), and this was 
overriding the route parameter.

## Data Structure
```
Trainee Table:
- Id: 19 (Primary Key - trainee's ID)
- UserId: 30 (Foreign Key - references User table)
- Email: aswin@gamil.com
- Other fields...
```

## The Issue

### Original Request
```
PUT /api/Trainees/19
Body: {
  "id": 30,  // ? WRONG - This is the UserId, not the trainee Id
  "email": "aswin@gamil.com",
  "phoneNo": "9023558234",
  "status": "Inactive"
}
```

### What Was Happening
Even though the route parameter was `19`, the request body contained `id: 30`, 
which could potentially override the route parameter depending on the order of 
model binding operations.

## The Fix

### Modified File
`IlpRepoBackend.Application\Command\Trainees\UpdateTraineeCommand.cs`

### Change Made
Added `[JsonIgnore]` attribute to the `Id` property to prevent it from being 
set via the JSON request body:

```csharp
public class UpdateTraineeCommand : IRequest<ApiResponse<TraineeDto>>
{
    [JsonIgnore]  // Prevent this from being set via JSON body
    public int Id { get; set; }
    
    public string? Email { get; set; }
    public string? PhoneNo { get; set; }
    public TraineeStatus Status { get; set; }
    // ... other properties
}
```

### How It Works Now

1. **Client sends request**: `PUT /api/Trainees/19` with body `{ ... }` (no id field)
2. **Controller receives**: Route parameter `id = 19`
3. **Controller sets**: `command.Id = 19` (from route parameter only)
4. **Handler uses**: `request.Id` which is guaranteed to be 19
5. **Lookup succeeds**: Finds trainee with Id=19, updates it

### Controller Code (unchanged, but now works correctly)
```csharp
[HttpPut("{id}")]
public async Task<IActionResult> Update(int id, [FromBody] UpdateTraineeCommand command)
{
    command.Id = id;  // Always uses route parameter, ignores body
    var result = await _mediator.Send(command);
    
    if (!result.Succeeded)
        return BadRequest(result);
        
    return Ok(result);
}
```

## Why This Happened

### Common Confusion Points

1. **Two ID Fields**: Trainees have both `Id` (primary key) and `UserId` (foreign key)
2. **Frontend Confusion**: Frontend might be sending UserId thinking it's the trainee ID
3. **Model Binding**: ASP.NET Core binds both route parameters and body properties
4. **Binding Order**: Body binding can happen before route parameter assignment

### Root Cause Analysis

The frontend was likely fetching trainee data and seeing:
```json
{
  "id": 19,
  "userId": 30,
  // ... other fields
}
```

Then when updating, it was using the wrong field in the request body.

## Best Practices Applied

### 1. Resource ID in URL Only
For UPDATE operations, the resource ID should ONLY come from the URL path, 
never from the request body.

```
? PUT /api/Trainees/{id}  - ID from URL
? PUT /api/Trainees with ID in body
```

### 2. JsonIgnore for Route-Bound Properties
Use `[JsonIgnore]` on properties that should not be set from JSON:

```csharp
[JsonIgnore]
public int Id { get; set; }
```

### 3. Clear Error Messages
Ensure error messages clearly indicate which ID is being used:

```csharp
return ApiResponse<TraineeDto>.Fail($"Trainee with ID {request.Id} not found");
```
