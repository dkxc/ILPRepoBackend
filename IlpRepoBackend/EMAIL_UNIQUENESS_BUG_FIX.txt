## ?? Critical Bug Discovered

**Bug**: Two trainees with the same email (`aswin@gamil.com`) were successfully 
created in the system, violating the email uniqueness constraint.

**Evidence from Production Data**:
```json
{
  "id": 19,
  "username": "aswin",
  "email": "aswin@gamil.com",
  "userId": 30
},
{
  "id": 26,
  "username": "merlin",
  "email": "aswin@gamil.com",  // ? DUPLICATE EMAIL
  "userId": 37
}
```

## Root Cause

The `CreateTraineeHandler` was **missing email uniqueness validation**. It only 
validated Aadhaar ID uniqueness but never checked if the email already existed.

### Original Code (BUGGY)
```csharp
public async Task<ApiResponse<TraineeDto>> Handle(
    CreateTraineeCommand request, 
    CancellationToken cancellationToken)
{
    // ? NO EMAIL VALIDATION HERE!
    
    // Check if AadhaarId already exists
    if (!string.IsNullOrEmpty(request.AadhaarId))
    {
        var aadhaarExists = await _traineeRepository.AadhaarIdExistsAsync(request.AadhaarId);
        if (aadhaarExists)
            return ApiResponse<TraineeDto>.Fail("A trainee with this Aadhaar ID already exists.");
    }

    // Create User (with duplicate email) ?
    var user = new User
    {
        Username = request.Username,
        Email = request.Email,
        // ...
    };
    // ...
}
```

## The Fix

Added email uniqueness validation **before** creating the user account:

### Fixed Code
```csharp
public async Task<ApiResponse<TraineeDto>> Handle(
    CreateTraineeCommand request, 
    CancellationToken cancellationToken)
{
    // ? NOW CHECKING EMAIL UNIQUENESS
    if (await _userRepository.EmailExistsAsync(request.Email))
        return ApiResponse<TraineeDto>.Fail("Email already exists");

    // Check if AadhaarId already exists
    if (!string.IsNullOrEmpty(request.AadhaarId))
    {
        var aadhaarExists = await _traineeRepository.AadhaarIdExistsAsync(request.AadhaarId);
        if (aadhaarExists)
            return ApiResponse<TraineeDto>.Fail("A trainee with this Aadhaar ID already exists.");
    }

    // Create User (only if email is unique) ?
    var user = new User
    {
        Username = request.Username,
        Email = request.Email,
        // ...
    };
    // ...
}
```

## Why This Bug Occurred

1. **Incomplete Implementation**: Email validation was implemented in the bulk 
   create handler but forgotten in the single create handler.

2. **No Database Constraint**: While the code checked for uniqueness, there was 
   no database-level unique constraint to prevent duplicates as a last resort.

3. **Documentation Mismatch**: API documentation stated "Email must be unique" 
   but the code didn't enforce it.
