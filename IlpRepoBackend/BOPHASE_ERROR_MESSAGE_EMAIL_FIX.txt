## ?? Issue Description

**Problem**: When a trainee already has a BO Phase assignment, the error message 
was confusing:

```
400 Bad Request: "Trainee nino already has a BO Phase assignment"
```

**Root Cause**: Multiple trainees can have the **same name** (usernames are NOT 
unique), so error messages using names are ambiguous. The error should identify 
the trainee by **email** (which IS unique).

## The Confusion

### Scenario
```
Database has:
- Trainee 1: name="nino", email="nino@gmail.com" ? Has BO Phase ?
- Trainee 2: name="nino", email="nino2@gmail.com" ? No BO Phase ?

User tries to create BO Phase for Trainee 1 again:
  ?
Error: "Trainee nino already has a BO Phase assignment"
  ?
Confusion: Which "nino"? There are 2 trainees with that name! ??
```

## Why Names Can Be Duplicate

### From API Documentation
```
Username is NOT required to be unique
Multiple trainees can share the same name
Email serves as the unique identifier
```

### Real-World Example
```javascript
// Valid scenario - two trainees with same name
[
  {
    id: 20,
    username: "John Smith",
    email: "john.smith1@example.com",
    batchId: 11
  },
  {
    id: 25,
    username: "John Smith",
    email: "john.smith2@example.com",
    batchId: 11
  }
]
```

Both have the name "John Smith" but different emails. Error messages must use 
email to avoid confusion.
